# Slot G350 0.1.9.2 — Dreamcast relaunch and rendering repair

Repairs the Dreamcast → PSP → Dreamcast crash reported on 0.1.9.1. The ARM64 regression reproduced it with the original core; six mixed launches pass with the repaired core, including Dreamcast state restoration.

Flycast's Linux libretro implementation retains the initialized emulator/recompiler between sessions but frees the virtual-memory reservation that contains their SH4 context. PSP can then occupy that address. On another Dreamcast launch the retained objects reference freed memory. The patch retains the single reservation alongside the already retained emulator objects. Later launches reuse it; additional reservations are not accumulated. Renderer contexts and audio buffers still close on exit.

Dreamcast retains GLES3 at 320×240 and per-triangle sorting. It now renders every other frame and uses maximum adaptive frame skipping when the renderer is busy. The emulated CPU clock and audio sample rate remain unchanged. This reduces rendering work at the expense of visual smoothness. Container measurements are not G350 frame-rate measurements; improved physical speed/audio quality still needs an owner test.

The frontend is built with `--no-default-features --features device`. Its packaged entrypoint is checked to select SDL KMS/DRM with no desktop display variables. PSP's core, settings and controls are unchanged. All N64/SNES/PS1/GBA/GB core payloads are unchanged. Hold Menu alone for one second to return to Slot; face buttons remain game controls.

Replace both SYSTEM and SYSTEM.md5 on PAN4ELC with the pair from `slot-g350-0.1.9.2-dreamcast-psp-update.zip`, with the device off. No reflash or format is needed. The startup script replaces only the known bundled 0.1.9/0.1.9.1 Flycast hash with the repaired core, using a temporary file and rename; custom core copies are preserved. Your games, artwork, VMU/memory-stick saves and Slot states remain on GAMES. Existing Dreamcast states use the same serialization format.

Keep the accepted 0.1.8 update ZIP as the stable base. 0.1.9.2 remains a candidate until tested on the handheld. The GitHub backup includes source/build instructions, corresponding source bundles, latest update and stable rollback. Games and proprietary BIOS files are excluded.

The lifecycle diagnosis was verified against [Flycast's upstream libretro implementation](https://github.com/flyinghead/flycast/blob/v2.5/shell/libretro/libretro.cpp). The patch and before/after regression records are included in the corresponding source bundle.
