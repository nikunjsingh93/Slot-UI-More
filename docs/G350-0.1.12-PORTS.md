# G350 0.1.12: Ports display and launcher repairs

Local update for the G350 only. This is a SYSTEM update for an existing card;
it does not erase games or saves. The nine emulator cores are unchanged from
0.1.11 (the original eight systems use the accepted 0.1.10 core files).

* Ports now use the same round CD renderer as PS1/Dreamcast. Square disc labels
  replace the previous rectangular cartridge labels on the owner's card.
* A dark Slot splash replaces the Pan4Elec userspace splash and return screen.
  Bootloader graphics are outside this SYSTEM update.
* A narrowly scoped input helper prevents GTA's gamepad grab from hiding the
  Menu button from Slot's quit monitor. Hold Menu alone for one second to quit.
* The current runner is refreshed at boot rather than keeping an older copy.
* The owner's clean Android 2.10 ARM64 GTA library replaces an injected
  PluginLoader variant. Its assets are checked against that APK. The clean
  library passes the constructor phase that previously faulted; actual handheld
  gameplay still requires testing. APKs, OBBs and extracted libraries stay local.
* PortMaster now has a verified offline catalogue cache, loaded through its
  real source parser (1,446 entries at preparation time; its complete offline
  startup lists 1,378 after filtering for the G350's capabilities). Browsing works offline;
  downloads and updates need internet. Individual port compatibility varies.
  NFS's port metadata is corrected to the current `runtime` schema.

Native ports use their own save functions. Slot's emulator save states, shaders
and Menu+X/Y shortcuts do not apply. Existing emulator controls are preserved.

## Installation and verification

Use `firmware/ports/install-update.ps1` with the matching local update ZIP and
manifest. It validates the target USB card's PAN4ELC/GAMES partitions, verifies
the archive, flushes both SYSTEM files, then reads the firmware directly from
the card without the Windows file cache. Games and save directories are not
rewritten by the SYSTEM installer. The separate game repairs are private.

The card also had a GAMES/exFAT allocation bitmap error and damaged GTA data.
Windows CHKDSK repaired the bitmap. The main OBB was restored, all 435 extracted
GTA assets were checked against the original archives/clean APK (four texture
files replaced), and all 1,219 NFS game files matched the originals. A temporary
save-protection copy was used only for the filesystem repair; saves are excluded
from game-data repair. Final uncached firmware/runtime/archive checks passed,
all 115 save/state file contents were unchanged, and the final filesystem scan
reported no problems. The temporary save copy was removed. No card reflash is needed.

The packaged frontend, runner, input helper and splash were extracted and
compared to their source builds. Frontend tests, shell syntax, dependency checks
and core hash checks passed. Input sharing passed a mock-device ioctl check.
PortMaster's own parser and complete All Ports listing loaded the cached
catalogue without network access.
These checks do not replace physical tests of launch, sound, controls and quit.

## NFS compatibility investigation

The upstream release's compiled guest manifest differs from the advertised
SPEED2.EXE: its CRT entry and import slots are inconsistent. An entry alias alone
does not repair this. No experimental executable patches are installed on the
card. A private full lift of the owner's executable generated 27,742 functions
with no translation failures. Its matching ARM64 runtime passed local startup,
profile creation/save and the main menu with the 3D car rendering. The private
binary was installed separately; it is not included in the SYSTEM or source
archive. The original EXE and game data are unchanged. Physical gameplay,
performance, sound and controls still need validation on the G350.

The other layout's address-specific native accelerations, resolution hooks,
widescreen writes and parallel guest-thread selection are disabled. This favors
compatibility and does not promise the upstream optimized build's frame rate.
The generic GLES/HLE backend and controller mapping remain. See the pinned
[private rebuild recipe](../firmware/ports/nfs/README.md). No experimental PE
patches are needed. Old address-specific accelerations must not be reused blindly.
