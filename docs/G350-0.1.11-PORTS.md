# G350 0.1.11: native Ports (hardware testing pending)

Adds a ninth Slot shelf, **Ports**, to the G350 0.1.10 base. Existing emulator
cores are retained byte for byte. This update is for the G350 only.

## Using it

Switch to the Ports shelf and launch Need for Speed Underground 2, Grand Theft
Auto San Andreas or PortMaster. **Hold the centre M/Menu button for one second**
to close the port and return to Slot. The game runs after Slot releases its
graphics/audio resources; Slot starts again after it ends. A port is never
automatically relaunched during startup. Short Menu presses do not trigger quit.

Use each game's own save function. Emulator Menu+X/Y save-state commands and
Slot shader options do not apply to these native games. Save before quitting:
Menu-hold requests termination and is not a guarantee that unsaved progress is
written. Button layouts come from the individual ports. NFS's default layout:
left stick steering; bottom B accelerate/confirm; left Y brake/reverse; right A
handbrake; top X camera; R1 nitrous; L1 rear view; L2/R2 manual gears; Start pause.

GTA's first run shows its setup screen: press **A**, then allow extraction to
finish. Leave several GB free and keep the handheld charged during setup.
Setup and actual performance must be verified on the handheld.

PortMaster's catalog requires an internet connection (typically a compatible
USB Wi-Fi adapter on the G350). The two installed games use local data. The GUI
is started directly with the firmware's Python/SDL libraries rather than its
generic EmulationStation/Love splash launcher. Downloaded top-level `.sh` ports
are added to the shelf when PortMaster closes or at next boot. Port-specific
runtimes, filesystem needs and compatibility still vary; this is not a claim
that every PortMaster game works. Scripts with unsupported filename characters
are not imported. Launch only scripts you trust.

## Files on the card

On GAMES (`E:` during this installation):

* `Slot/Games/PORTS/*.port`: small launch descriptors, not ROMs.
* `Slot/Labels/PORTS/*.png`: shelf labels.
* `Slot/System/slot-port-runner.sh`: native launch settings.
* `ports/PortMaster`: PortMaster runtime and downloaded ports support.
* `ports/nfsu2/gamedata`: the owner's PC NFSU2 installation; must contain
  `SPEED2.EXE`, `GLOBAL`, `CARS`, `TRACKS`, etc.
* `ports/gtasa/gtasa.apk`: the owner's Android **2.10** APK with ARM64 library.
* `ports/gtasa/main.obb` and `patch.obb`: the owner's main.8/patch.8 OBBs,
  copied under real filenames because the card is exFAT.

NFS's verified executable SHA256:
`f9dd86c054878ce6276beb07c1fd61874f7a1e4bf1f241b084c65b73e24168a7`.
NFS uses the upstream performance graphics preset, 200 m draw distance, 4:3 and
a 30 FPS cap. This is a target, not a measured G350 frame rate. No overclock or
exFAT swap file is enabled.

Logs: `Slot/Config/ports.log`, `ports/nfsu2/log.txt`, `ports/gtasa/gtasa.log`,
and `ports/PortMaster/log.txt` if produced by PortMaster. SDL uses the base's
explicit ALSA plug through AUDIODEV, and OpenAL uses a per-port config; existing
audio routing remains active.

## Updating / reverting

The first installed copy failed before frontend startup. Reconnecting the card
showed about 69 MB of SYSTEM data differed from the intact archive, including
erased `FF` blocks. The FAT32 directory check was clean. A write-through rewrite
with an explicit disk flush passed a complete uncached SD read. This establishes
the bytes at the time of that check, but a later write to GTA's separate data
file changed SYSTEM again. A 512-byte changed sample matched GTA source data,
so storage addressing/transfer reliability was investigated. After the owner
changed reader, SYSTEM was rewritten again; both SYSTEM and GTA's main data
then passed uncached checks together. All 1,219 NFS game files also passed.
This implicates the previous transfer path, but does not conclusively identify
the faulty hardware component. Physical boot acceptance is still pending.
The firmware payload is unchanged by this transfer repair.

For Windows, `firmware/ports/install-update.ps1` accepts `-ArchivePath` and
`-ManifestPath` (the 0.1.11 manifest). It checks the connected G350 volume labels,
uses write-through and `Flush(true)`, then reads SYSTEM with Windows file caching
disabled. Default letters are D for PAN4ELC and E for GAMES; override with
`-BootDrive` / `-GamesDrive`. `-VerifyOnly` checks without rewriting. Safely eject
through Windows after completion. The earlier Python cached-copy installation
path is superseded by this helper.

With the handheld off, replace SYSTEM and SYSTEM.md5 on PAN4ELC using the
0.1.11 update archive. Extract the separate runtime archive onto GAMES, merging
the Slot/ports directories. Supply your own game files as above. Never copy
the G350 SYSTEM onto the Anbernic cards. No fresh image is provided for 0.1.11.

To revert the frontend, restore SYSTEM and SYSTEM.md5 from the retained 0.1.10
update. The extra Ports folders can remain; the old frontend ignores them.
There is no need to reflash the whole card or copy existing ROMs again.

## Build and validation

Frontend: build `slot/` on AArch64 with `cargo build -p slot --release
--no-default-features --features device` and `RUSTFLAGS=-C target-cpu=cortex-a35`.
Compile `firmware/ports/portwatch.c` with `gcc -O2 -static -o slot-portwatch`.
Run `python3 firmware/ports/test_portwatch.py` after adjusting its binary path,
or run the supervisor's `--self-test`. Patch an extracted 0.1.10 SYSTEM using
`firmware/ports/patch_system.py`, then repack with mksquashfs gzip, block 131072.
Preserve all base boot files, drivers, core binaries and the existing launcher
audio/performance setup.

Passed: device frontend compilation; 48 frontend library tests; store/UI tests;
Ports descriptor scanner regression; descriptor path/command rejection;
supervisor short/long Menu process tests; native binaries' library resolution;
PortMaster GUI imports in the exact firmware Python. Physical boot, graphics,
controls, audible output and game speed remain hardware acceptance tests.
