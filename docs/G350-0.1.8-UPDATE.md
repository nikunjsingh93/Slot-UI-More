# Slot G350 0.1.8 experimental update

N64 now defaults to ParaLLEl N64 with Glide64 GLES2, HLE RSP, the dynamic
recompiler and 320×240 output. This is a 64-bit build for the existing Slot
runtime, not the 32-bit variant reported in the gameplay video.

The previous GLideN64 renderer has higher hardware requirements than the
legacy plugins available in ParaLLEl. See the [Libretro documentation](https://docs.libretro.com/library/parallel_n64/).
Performance and graphical compatibility still depend on the game.

Slot keeps the existing N64 button mapping and one-second Menu hold to return
to the shelf. SNES/PS1 fixes, speaker/headphone routing, circular discs and
display sizing remain. This update adds no standalone emulator.

CPU, GPU and memory-controller performance governors use their existing
frequency limits. No frequencies or overclock unlock flags are changed.
The base firmware's normal Max Performance profile also includes the memory
governor; our previous startup script only set CPU and GPU governors.

New log lines report average console processing time, frames exceeding their
time budget, queued audio and audio starvation every five seconds. This helps
identify what is limiting performance on the actual G350.

## Installation

For an existing Slot G350 card, replace `SYSTEM` and `SYSTEM.md5` together on
the PAN4ELC boot partition using `slot-g350-0.1.8-parallel-n64-update.zip`.
No complete flash is needed. Safely eject the card after both files finish
copying, then boot. The new core is provisioned into Slot/System on first boot.
Games, artwork, configuration and saves on the GAMES partition are preserved.

N64 in-game save memory uses the same 296,960-byte layout in both cores.
Save states are stored separately by core; previous Mupen64Plus-Next states
remain available with that core. N64 automatic resume remains disabled to
avoid crash loops.

If needed, retain a game's old core through `Slot/Config/selected_core.ini`:

```ini
Re-Volt = mupen64plus_next
```

Use the exact game's filename without extension. Remove its override to use
the new ParaLLEl default, or set it to `parallel_n64` explicitly.

## Validation and next device check

Re-Volt, Wave Race and V-Rally passed 1,200-frame core checks for graphics,
PCM generation, save-state round trips and preserved ARM64 registers. Each
also passed 60 seconds through the complete Slot frontend and Menu-hold exit.
Library, input, storage, console audio regression and boot recovery tests,
production Clippy checks, package hashes, ZIP integrity, full SquashFS
extraction and firmware dependency checks passed.

These tests used an ARM64 container with Mesa software GLES and an ALSA null
device. They do not measure physical G350 frame rates or audible quality.
The reported benchmark scenes are automated startup/menu sequences, not a
controlled comparison of complete races. Hardware performance remains to be
tested by the owner; full-speed N64 is not guaranteed.

After booting, try the same three games. If stuttering continues, play one for
30–60 seconds, hold Menu to return to Slot and reconnect the card so the new
performance lines in Slot/slot.log can be examined.

Corresponding sources: `slot-g350-0.1.8-sources.zip`. The pinned ParaLLEl source,
Cortex-A35/GLES2 build recipe and ARM64 context-switch repair are included.
No commercial games, artwork from the card or personal saves are packaged.
