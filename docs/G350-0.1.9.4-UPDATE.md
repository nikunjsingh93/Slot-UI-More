# G350 0.1.9.4 audio and UMD update

For an existing BATLEXP G350 Slot installation. With the handheld off, replace
both SYSTEM and SYSTEM.md5 on PAN4ELC with the matching pair in
slot-g350-0.1.9.4-audio-umd-update.zip. Safely eject before booting. No reflash is
needed. Keep the 0.1.9.3 update ZIP as the rollback pair.

## Dreamcast sound

The owner reports that 0.1.9.3 improved Dreamcast speed substantially, with
SoulCalibur almost full speed, but sound still stutters. Card logs show the
audio queue emptying between bursts of PCM. This update targets those gaps.

Dreamcast alone uses a 320 ms PCM capacity with a 160 ms target, replacing the
usual roughly 133 ms capacity / 67 ms target. It delivers PCM before publishing
video and avoids an extra idle sleep when Flycast returns an empty audio batch
while the output queue needs data. Producer waits remain bounded. Switching
systems restores the original audio profile.

This adds about 93 ms of target audio latency. It absorbs short rendering
stalls; it cannot make sustained emulation below real time produce enough sound.
Audible results still require testing on the handheld.

The faster 0.1.9.3 GLES3 readback and renderer settings are retained. All emulator
core binaries, CPU/audio clocks, hardware frequency limits, save-state formats,
PSP gameplay settings and accepted SNES/N64/PS1 settings are unchanged.

## PSP UMD and Studio

The PSP shell is now 312x328 with a round window, narrow rim and wider lower
base, following the supplied UMD reference. Scanned labels retain their printed
centre. Older Studio labels with a CD-style hole display a replacement opaque
UMD hub; their files do not need to be edited. Studio v4 uses the same geometry
and no longer cuts a spindle hole through new PSP scan labels. PS1/DC spindle
holes are retained. The local v3 filename also opens the updated Studio.

A separate startup bug was found: the firmware's BusyBox cp -n skipped the
existing empty PSP asset directory. Missing bundled fonts/shaders/support files
are now copied individually on boot. Existing files are preserved, and an
interrupted copy can be retried.

## Validation

- Dreamcast buffer regression covers a 120 ms graphics gap and profile reset.
- Timed PCM consumption stays continuous through empty-audio calls followed by
  100 ms rendering/audio bursts. Existing SNES/PS1 continuity tests pass.
- The owner's SoulCalibur state restores with changing video and nonzero PCM.
- Six mixed Dreamcast/PSP launches and state round trips pass; holding Menu
  alone returns the full frontend to the shelf.
- Offline Studio tests cover the opaque PSP centre, unchanged DC hole, shell
  geometry and existing local label rendering. Portable source rebuild matches
  the delivered HTML byte for byte. No online card-artwork refresh was run.
- Actual firmware BusyBox copies 189 assets into an existing empty folder,
  repairs a missing file on retry and preserves an existing modified asset.
- Shipping device build selects KMS/DRM; runtime dependencies resolve. Core
  hashes match 0.1.9.3; the matching SYSTEM pair and ZIP CRC are checked.

Container graphics use Mesa software rendering. These checks establish
correctness, not handheld frame rates or audible quality. See the installed
receipt for SD read-back verification after copying.

Hold Menu alone for one second to quit to Slot. Test SoulCalibur gameplay and
sound, resume its state, then launch PSP and Dreamcast again. The next
Slot/slot.log records the new PCM profile and audio counters.

Only necessary frontend/build/Studio files and release documentation are backed
up to the private GitHub repository. Unchanged corresponding core sources
remain in release v0.1.9.2. No games, user saves or proprietary BIOS are uploaded.
