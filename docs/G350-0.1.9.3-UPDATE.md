# G350 0.1.9.3 Dreamcast performance update

For an existing BATLEXP G350 Slot installation. Replace both SYSTEM and
SYSTEM.md5 on PAN4ELC with the pair in the update ZIP, with the handheld off.
Safely eject the card before booting. A complete reflash is unnecessary.
Keep the previous 0.1.9.2 update ZIP as a rollback pair.

## Changes

- Dreamcast GPU framebuffer allocation now follows the configured 320x240
  resolution, rather than the core's generic 640x480 base geometry. This uses
  75% fewer framebuffer pixels. The previous image readback was already 320x240.
- A bounded queue of three GLES3 pixel-pack buffers reads completed GPU frames
  without waiting on fences. When all buffers are busy, it retains the previous
  picture and continues emulation. Unsupported/failed drivers fall back to the
  synchronous path. This adds a small display delay and can drop display frames.
- Lighter per-strip transparency sorting and disabled modifier volumes follow
  dArkOS's RK3326 RetroRun defaults. RTT readback, deferred frame swapping,
  anisotropic filtering and texture upscaling are disabled. These options were
  checked against the actual bundled Flycast v2.5 core's supported values.
- Existing 320x240 threaded rendering, fixed frameskip 1 and maximum adaptive
  skipping remain. Emulated CPU and audio clocks remain unchanged.

All emulator core binaries are identical to 0.1.9.2, retaining its Dreamcast
relaunch repair and save-state format. PSP and the accepted SNES/N64/PS1 settings,
audio routing and hardware clock limits are unchanged. Hold Menu alone for one
second to quit to Slot. X/Y alone remain game buttons.

## Research and limits

[dArkOS RK3326 defaults](https://github.com/christianhaitian/dArkOS/blob/master/retrorun/configs/retrorun.cfg.rk3326)
use threaded rendering, fast per-strip sorting, disabled DSP/modifier volumes,
and no texture upscaling. Its older core's option names/values are not all valid
for Flycast v2.5, so they were not copied blindly.

[RetroRun's recent RK3326 profiles](https://github.com/navy1978/retrorun/blob/master/profiles/flycast2022-lowend/README.md)
also use game-specific renderer changes in a modified Flycast 2022 core. Their
Virtua Tennis results are tied to exact product numbers and visual checks.
Those experimental per-vertex depth and geometry-merge patches are not enabled
here; using another core can also invalidate existing save states.

Fast per-strip sorting and disabled modifier volumes trade transparency/shadow
accuracy for speed. Some titles can still need a different profile. Full-speed
Dreamcast across every game is not promised on RK3326.

## Validation

Passed 60 slot-retro tests, including GLES3 colour conversion, buffer resize and
context teardown. The owner's existing Virtua Tennis and Crazy Taxi 2 states
restore with graphics and nonzero PCM; new state round trips pass. Six mixed
Dreamcast/PSP launches pass, followed by full Slot long-press Menu exit. The
shipping executable selects KMS/DRM, dependencies resolve, and the ZIP CRC and
SYSTEM/MD5 pair are verified.

These run in an ARM64 container with Mesa software rendering. They establish
correctness, not G350 frame rates or audible quality. Physical speed/audio
validation remains pending. Test Virtua Tennis, including resuming your state,
then PSP and Dreamcast again. The next Slot/slot.log will show the active
GLES3 readback queue and emulation/audio performance counters.

No games, game states or proprietary BIOS are included. Current frontend source
and necessary build files are backed up in the private GitHub repository; the
unchanged core source archives remain under release v0.1.9.2.
